# tque 利用マニュアル

[English](user-manual.md) | [日本語](user-manual.ja.md)

対象: tque 0.1.0

Windows版の対象はWindows 11です。インストーラーはビルド22000以上を要求し、Windows 10にはインストールできません。macOS用ファイル名の`darwin`はmacOSを表します。

tqueは、ターミナルで使うタスク管理アプリです。コマンドを実行するCLIと、キーで一覧を操作するTUIを利用できます。両方とも同じ保存データを使います。

## 起動する

実行ファイルはWindows、macOS、Linux向けです。OSとCPUに合うものを使用してください。`amd64`はx64、`arm64`はARM64向けです。実行時にGoや外部データベースは必要ありません。ビルド方法・ActionsのZIP取得方法は[README](../README.ja.md)、OSごとの検証状況は[実装・検証記録](implementation-status.md)を参照してください。

WindowsのPowerShellで、カレントディレクトリにある実行ファイルを起動する例です。

```powershell
.\tque.exe
```

ZIPを展開し、実行ファイルのあるディレクトリで起動してください。macOS / Linuxの例です。

```sh
./tque
```

Unixの展開ツールが実行権限を保持しなかった場合は、`chmod +x ./tque`で付与してください。ZIPは未署名で、macOSでの実行・署名・公証は未検証です。

以降のコマンド例は、実行ファイルを`tque`という名前でPATHの通った場所に配置した場合の表記です。直接起動する場合は、先頭の`tque`を`.\tque.exe`など、使用する実行ファイルのパスに置き換えてください。

```text
tque
tque --tui
tque --help
tque --version
tque add --help
```

引数なし、または`--tui`でTUIが開きます。TUIには対話操作できる端末が必要です。`--tui`と`ls`などのサブコマンドは併用できません。

## 最初のタスクを登録する

### TUIで試す

1. `tque`を起動します。
2. `a`を押し、`資料を作成する`と入力してEnterを押します。
3. 登録したタスクを選び、`d`を押して`+7d`を入力し、Enterで期日を保存します。
4. `A`（大文字）を押し、`構成を考える`と入力してEnterを押すと、子タスクができます。
5. 子タスクを選んでSpaceを押すと完了になります。
6. Enterで詳細を確認し、Escで一覧へ戻ります。`q`で終了します。

変更は操作ごとに保存されるため、終了時の保存操作は不要です。入力途中の内容はEnterで確定するまで保存されません。

### CLIで試す

以下のID `1`、`2`、`3`は、まだタスクを登録していない保存先で順番に実行する例です。既存データがある場合は、追加時に表示された実際のIDに読み替えてください。

```text
tque add "資料を作成する" --due +7d
tque add "構成を考える" --parent 1
tque add "本文を書く" --parent 1 --dep 2
tque ls --all --tree
tque done 2
tque ls --ready
```

「本文を書く」は「構成を考える」が未完了の間は依存待ちになります。タスク2を完了すると依存待ちが解消します。親タスクも着手可能の条件を満たせば、`--ready`の結果に含まれます。

## 実行例：資料作成を進める

以下は、空の保存先に3件を登録してから完了するまでの実行例です。`>`は入力行の目印で、入力する必要はありません。その下の行が実際の出力です。既存データがある場合は、`add`の出力に表示されたIDを使い、以下の`1`・`2`・`3`を置き換えてください。前節の例を実行済みの場合は同じタスクが追加されます。既存データを消してやり直す必要はありません。

### 1. 親タスク・子タスク・依存関係を登録する

```text
> tque add "資料を作成する"
[+] Created task #1: 資料を作成する
> tque add "構成を考える" --parent 1
[+] Created task #2: 構成を考える
> tque add "本文を書く" --parent 1 --dep 2
[+] Created task #3: 本文を書く
> tque ls --all --tree
1 [ ] 資料を作成する [.......... 0%]
├─ 2 [ ] 構成を考える [.......... 0%]
└─ 3 [ ] 本文を書く [.......... 0%] (blocked by #2)
```

`blocked by #2`は、タスク2が未完了のため本文作成が依存待ちであることを示します。

### 2. 進捗を更新する

```text
> tque edit 2 --progress 50
[*] Updated task #2
> tque ls --all --tree
1 [ ] 資料を作成する [##........ 25%]
├─ 2 [ ] 構成を考える [manual] [#####..... 50%]
└─ 3 [ ] 本文を書く [.......... 0%] (blocked by #2)
```

子タスクの進捗が50%と0%なので、親の自動進捗は25%になります。`[manual]`は手動で指定した進捗を示します。

### 3. 依存待ちを解消する

```text
> tque done 2
[x] Completed task #2
> tque ls --ready
1 [ ] 資料を作成する [#####..... 50%]
3 [ ] 本文を書く [.......... 0%]
```

タスク3が着手可能になり、依存待ちの表示が消えます。親タスク1も着手可能の条件を満たすため表示されます。

### 4. 子タスクと親タスクを完了する

```text
> tque done 3
[x] Completed task #3
> tque ls --all --tree
1 [ ] 資料を作成する [########## 100%]
├─ 2 [x] 構成を考える [manual] [########## 100%]
└─ 3 [x] 本文を書く [########## 100%]
> tque done 1
[x] Completed task #1
> tque ls --all --tree
1 [x] 資料を作成する [########## 100%]
├─ 2 [x] 構成を考える [manual] [########## 100%]
└─ 3 [x] 本文を書く [########## 100%]
```

子がすべて完了すると親の進捗は100%になりますが、親の完了状態は自動では変わりません。`done 1`で親も完了にします。完了したタスクを表示するには`--all`を付けます。

### 5. TUIで結果を確認する

`tque`を起動すると、同じ3件がツリーに表示されます。起動済みなら`r`で再読み込みし、`f`で全件表示にしてください。親を選択して←で折り畳み、→で展開できます。Enterで詳細、Escで一覧へ戻ります。

試用後にこの3件だけを削除する場合は、`tque ls --all --tree`で親のIDと子を確認してから、`tque rm 1 --cascade`を実行します。`1`は実際の親IDに置き換えてください。このコマンドは確認なしで親と子を削除します。

## TUIで操作する

### 画面の見方

初期表示は全件のツリーです。上部に保存先や検索・絞り込み条件、中央に一覧、下部に選択タスクの情報・通知・キー案内を表示します。通知や保存先が画面に収まらない場合は`?`で全文を確認できます。

| 表示 | 意味 |
| --- | --- |
| 行頭の`>` | 選択中のタスク |
| `[ ]` / `[x]` | 未完了 / 完了 |
| 親タスクの`v` / `>` | 展開中 / 折り畳み中 |
| `[manual]` | 進捗を手動で指定している |
| `[context]` | 条件に一致した子の位置を示すために表示している祖先 |
| `!dep` | 未完了の依存先がある |
| 期日末尾の`!` | 未完了で期日を過ぎている |
| `#`と`.`のバー、または割合 | 表示上の進捗 |

80桁×24行を基準に表示を調整します。狭い画面では進捗バー・期日・下部の詳細を順に省略します。全文はEnterで開いて確認してください。40桁×10行未満では通常操作ができないため、端末を広げるか`q` / Ctrl+Cで終了します。

### 一覧のキー操作

| キー | 操作 |
| --- | --- |
| ↑ / ↓、`k` / `j` | 前 / 次のタスクへ移動 |
| PageUp / PageDown | ページ単位で移動 |
| ← | 展開中の親を折り畳む。それ以外は親へ移動 |
| → | 折り畳んだ親を展開する。それ以外は表示中の子へ移動 |
| Enter | 選択タスクの全文詳細を開く |
| `a` | 親なしのタスクを追加 |
| `A` | 選択タスクの子を追加 |
| `e` | タイトルを編集 |
| `s` / `d` | 開始日 / 期日を編集 |
| `p` | 進捗を編集。`0`〜`100`または`auto` |
| `l`（小文字のエル） | 依存先を編集。例: `2,3` |
| Space | 完了 / 未完了を切り替え |
| `+` / `-` | 進捗を10ずつ変更し、手動進捗に切り替え |
| `x` / Delete | 削除確認を開く |
| `/` | タイトル検索を開始 |
| `f` | 全件→未完了→今日まで→期限超過→着手可能→全件 |
| `o` | ID順 / 期日順を切り替え |
| Esc | 検索を解除。`f`の絞り込み条件は維持 |
| `r` | データを再読込 |
| `?` | ヘルプを開く |
| `q` / Ctrl+C | 終了 |

親の付け替え・親子関係の解除はCLIの`edit --parent`を使用してください。完了済みタスクで`+` / `-`は進捗を変更しません。先にSpaceで未完了へ戻します。

### 入力・詳細・削除確認

属性の入力中はEnterで保存、Escで取消です。開始日・期日・依存先は入力を空にしてEnterを押すと解除できます。進捗は空欄では解除できません。自動計算に戻す場合は`auto`を入力します。

入力中の← / →は文字カーソル移動です。Home / End、Ctrl+A / Ctrl+Eで先頭・末尾へ移動し、Backspace / Deleteで文字を削除できます。`q`、`j`、`k`、`?`なども文字として入力されます。Ctrl+Cは未確定の入力を保存せず終了します。

全文詳細は閲覧専用です。↑ / ↓、`j` / `k`、PageUp / PageDownでスクロールし、Escで戻ります。詳細画面の`q`はアプリを終了します。ヘルプは`?`またはEscで閉じます。

削除確認には選択タスクのIDと、非表示の子孫を含む削除総件数が表示されます。子孫の一覧は表示しないため、事前にツリーを展開して対象を確認してください。`y`で実行、`n`・`q`・Esc・Enterで取り消します。削除の取り消し機能（Undo）はありません。対象外のタスクから依存されている場合は削除できません。

### 検索と絞り込み

`/`に続けて文字を入力すると、タイトルを大文字・小文字を区別しない部分一致で検索します。Enterで検索条件を維持して一覧操作へ戻り、入力中のEscで検索開始前の条件へ戻ります。正規表現やあいまい検索には対応していません。

検索と`f`の条件は両方を満たすタスクに適用されます。一致タスクの祖先は`[context]`付きで残りますが、一致件数には含まれません。検索・絞り込み中は該当する枝が展開され、左右キーは親子の移動に使います。条件を解除すると元の折り畳み状態へ戻ります。

「今日まで」は今日が期日の未完了タスクと期限超過タスク、「期限超過」は昨日以前が期日の未完了タスクです。「着手可能」は未完了で、未完了の依存先がなく、開始日が未設定または今日以前のタスクです。

### 別のtqueと同時に使う場合

CLIなどで行った変更は、TUIの`r`で再読込してください。外部の変更を自動監視する機能はありません。`r`は設定ファイルを再読込しません。

保存中はCtrl+Cで終了を予約し、保存成功を確認してから終了します。`q`を含むその他のキー入力は無視されます。失敗した場合は画面に留まって通知します。

編集内容が別プロセスの更新と競合した場合、最新データを読み込み、編集案を保持して再確認を求めます。最新の内容を確認してから再度Enterで確定するか、Escで取り消してください。

編集対象が削除されていた場合は編集を中止し、入力案を通知に残します。

## CLIで操作する

### コマンド一覧

| コマンド | 用途 |
| --- | --- |
| `tque add "タイトル"` | 追加 |
| `tque edit ID 属性オプション` | 指定した属性を変更 |
| `tque done ID` | 完了にする |
| `tque undone ID` | 未完了に戻す |
| `tque rm ID` | 削除 |
| `tque rm ID --cascade` | 対象とすべての子孫を削除 |
| `tque ls` | 未完了を一覧表示 |

CLIの削除には対話確認がありません。実行前に`ls --all --tree`で対象を確認してください。子を持つタスクの削除には`--cascade`が必要です。削除範囲外からの依存がある場合は、`--cascade`を指定しても削除できません。

### 追加・編集の属性

| オプション | 指定内容 |
| --- | --- |
| `-t`, `--title` | タイトル。`edit`専用 |
| `-s`, `--start` | 開始日 |
| `-d`, `--due` | 期日 |
| `-p`, `--progress` | `0`〜`100`、または`auto` |
| `--parent` | 親タスクのID |
| `--dep` | 依存先ID。カンマ区切り・繰り返し指定が可能 |

```text
tque add "動作確認" --start today --due +3d -p 20
tque edit 3 --title "本文の初稿を書く" --start today --due +5d
tque edit 3 --dep 2,4 --dep 5
tque edit 3 --parent 1
tque edit 3 --parent none --dep none --start none --due none
```

`edit`では省略した属性を変更しません。依存先の指定は既存の一覧への追加ではなく、一覧全体の置き換えです。上の`--dep`例では依存先が2・4・5になります。存在するIDを指定してください。

`none`で親・依存先・開始日・期日を解除できるのは`edit`だけです。`add`では不要な属性を省略します。複数属性をまとめて変更し、その一つが不正だった場合は、変更全体が保存されません。

タイトルは前後の空白を除いて1〜200 Unicodeコードポイントです。見た目が1文字の絵文字でも、複数のコードポイントからなる場合があります。改行・タブなどの制御文字は使えません。空白を含むタイトルは引用符で囲んでください。

### 日付

| 書式 | 例 | 意味 |
| --- | --- | --- |
| `YYYY-MM-DD` | `2026-11-01` | 指定した日 |
| `today` | `today` | 操作した日のローカル日付 |
| `+Nd` | `+7d` | 操作した日からN日後 |

`+Nd`のNは0〜36500です。時刻は指定しません。開始日と期日の両方を設定する場合は、開始日が期日以前でなければなりません。必要なら一回の`edit`で両方を変更してください。

### 一覧・検索・並べ替え

| オプション | 表示内容 |
| --- | --- |
| `--all` | 完了済みも含める |
| `--tree` | 親子関係をツリーで表示 |
| `--search "文字列"` | タイトルの部分一致検索 |
| `--blocked` | 未完了の依存先があるタスク |
| `--due-today` | 今日までが期日の未完了タスク。期限超過を含む |
| `--overdue` | 昨日以前が期日の未完了タスク |
| `--ready` | 着手可能な未完了タスク |
| `--sort id` | ID順。既定値 |
| `--sort due` | 期日順。期日なしは最後、同じ期日はID順 |
| `--json` | JSON配列を出力 |

```text
tque ls --all --tree
tque ls --search "資料" --sort due
tque ls --due-today
tque ls --ready --json
tque ls --all --blocked
```

複数の条件はAND条件です。`--all`と併用しても`--due-today`・`--overdue`・`--ready`は未完了だけを対象にします。`--tree`では一致した子の祖先も表示するため、完了済みの親が表示される場合があります。ツリーの並べ替えは同じ親の子同士で行います。

`--tree`と`--json`、`--ready`と`--blocked`は併用できません。JSONは平坦な配列で、保存されたタスク属性に加えて、表示進捗`effective_progress`、依存待ち`blocked`、未完了の依存先`blocked_by`を含みます。`ls --json`は既定では未完了のみです。完全なバックアップには保存ファイルを使用してください。

### 実行結果と終了コード

追加時の`Created task #番号`が新しいIDです。`Unchanged task`は変更がなかったことを示します。通常の一覧が空の場合は「対象なし」、JSONでは`[]`を出力します。エラーは標準エラー出力へ出力します。

| 終了コード | 意味 |
| --- | --- |
| 0 | 成功 |
| 1 | タスク操作・設定・保存などのエラー |
| 2 | 引数やオプションの指定エラー |
| 3 | 保存結果を確定できない状態。再読込して確認が必要 |

終了コードはPowerShellで`$LASTEXITCODE`、Bash / Zshで`$?`、Fishで`$status`を実行直後に確認できます。

保存成功後にロック解放が失敗した場合、CLIは保存済みの結果（追加なら新しいID）を表示し、標準エラーに`saved; unlock failed`を出して終了コード1を返します。変更が取り消されたわけではありません。再実行前にデータを確認し、終了コードが0以外という理由だけで`add`を自動再試行しないでください。

## 親子関係・依存関係・進捗

親子関係は作業の内訳、依存関係は先に済ませたい作業を表します。子にしただけでは親への依存は設定されません。

`--dep 2`は「このタスクはタスク2に依存する」という指定です。依存先が未完了なら依存待ちになります。ただし依存待ちは警告であり、編集や完了を禁止しません。完了済みのタスクにも未完了の依存先があれば依存待ち表示が付きます。自分自身への参照や循環する関係は登録できません。

進捗には次の二つのモードがあります。

- **自動（auto）**: 既定のモードです。未完了の親は、直下の子の表示進捗の平均を小数点以下切り捨てで表示します。子がない場合は保持している進捗値を表示します。新規作成時は0です。
- **手動（manual）**: 数値を指定すると切り替わります。子の進捗に関係なく指定値を表示します。`edit ID -p auto`またはTUIの`p`→`auto`で自動へ戻せます。

例えば、直下の子が20%と80%なら、自動進捗の親は50%です。階層が深い場合も各親が直下の子を集計します。すべての末端タスクを一括して平均する方式ではありません。

**進捗100%と完了は別です。** `-p 100`だけでは完了になりません。`done`またはSpaceで完了にすると進捗は100%になりますが、子タスクは完了しません。

完了済みタスクにCLIで100未満の進捗を設定すると拒否されます。先に`undone ID`で未完了へ戻してから`edit ID -p 数値`を実行してください。

`undone`で未完了に戻しても、保持している進捗値は100%のままです。手動進捗なら必要に応じて数値を下げてください。自動進捗の親は再び子から計算します。自動へ切り替えても保持値を0へ戻さないため、最後の子を削除すると以前の保持値が表示されます。

## 保存先を設定する

### 設定ファイル

設定ファイルは全OS共通で`~/.tque/config.json`です。`~`は利用者のホームディレクトリを表します。Windowsでは通常`C:\Users\ユーザー名`です。

設定ファイルは自動作成されません。保存先を変える場合は`.tque`ディレクトリを作り、UTF-8の`config.json`を用意してください。既存の設定ファイルがある場合は内容を確認してから編集します。

```json
{
  "data_dir": "~/tque-data"
}
```

WindowsでDドライブを指定する例です。

```json
{
  "data_dir": "D:/tque-data"
}
```

JSON内でバックスラッシュを使う場合は`"D:\\tque-data"`のように二重にします。`/`を使うとこのエスケープが不要です。

| 設定 | 解釈 |
| --- | --- |
| 設定ファイルなし、または`{}` | 保存先は`~/.tque` |
| `"data_dir": "~/tque-data"` | ホーム直下の`tque-data` |
| `"data_dir": "data"` | 設定ファイルのある場所を基準にした`~/.tque/data` |
| 絶対パス | その場所を使用。OSに合うパスを指定 |

設定キーは`data_dir`だけです。コメント、未知のキー、重複キー、`null`、空のパスは使えません。`%USERPROFILE%`や`$HOME`などの環境変数は展開しません。設定が不正な場合はエラーで停止し、別の保存先へ切り替えることはありません。

空でないパスの前後の空白は除去しません。例えばUnixの`" /data"`は`/data`ではなく、先頭に空白を含む相対パスです。空白を含む正当なディレクトリ名を保持する仕様なので、貼り付け時の余分な空白に注意してください。

設定変更後はtqueを再起動してください。TUIの`r`では反映されません。設定ファイルの場所を変えるコマンドオプションはありません。

### 既存データを別の場所へ移す

保存先を変更しても、既存データは自動移動されません。

1. すべてのtqueを終了します。
2. 現在の保存先の`tasks.json`と、存在する`tasks.json.backup`を別の場所へコピーして保全します。現在の設定も控えます。
3. 新しい保存先として、他のタスクデータが入っていないディレクトリを用意します。
4. 現在の`tasks.json`を新しい保存先へコピーします。内容の一部だけを抽出せず、ファイル全体をコピーします。まだタスクを作っていなければ、この手順は不要です。
5. `config.json`の`data_dir`を新しい保存先へ変更します。
6. `tque ls --all --tree`で内容を確認し、TUIのヘルプで保存先を確認します。

確認できるまで元のデータを残してください。`lock`や一時ファイルを新しい保存先へコピーする必要はありません。

## バックアップと復旧

保存先には次のファイルを使用します。

| ファイル | 用途 |
| --- | --- |
| `tasks.json` | タスクとID採番・更新管理情報の本体 |
| `tasks.json.backup` | 実際の更新前の本体を保存する1世代のバックアップ |
| `lock` | 複数プロセスの同時アクセスを調整するOSロック用ファイル |
| `tasks.json.tmp`、`tasks.json.backup.tmp` | 保存処理の一時ファイル |

初回保存、内容の変わらない操作、入力エラーではバックアップを新しく作りません。バックアップは更新のたびに置き換わるため、削除や編集の履歴としては使えません。定期的な保全では、すべてのtqueを終了して保存ファイル全体を別の場所へコピーしてください。同じ保存先の1世代バックアップだけでは、保存媒体の故障には備えられません。

`lock`が残っていること自体は異常ではありません。ファイルを削除してロックを解除しようとしないでください。ネットワーク共有や同期ソフトによる同時変更は保証対象外です。

既存の保存先を読む際にも、`lock`を読み書き用に開くか作成します。`ls`にもロックの利用権限が必要で、ファイルがなければ作成権限も必要です。読み取り専用の保存先では、`tasks.json`自体が読めてもtqueでは読めない場合があります。ロックを省略せず、退避データの確認には書き込み可能な検証用ディレクトリへコピーしてください。

### データが壊れた場合

自動復旧や専用の復元コマンドはありません。まずすべてのtqueを終了し、現在の本体・バックアップ・残った一時ファイルを別の場所へ保全します。壊れた本体を削除して空の状態で使い続けたり、一時ファイルをそのまま本体に置き換えたりしないでください。

古いバックアップをそのまま上書きすると、削除済みIDの再利用や更新番号の巻き戻りが起こり得ます。復旧時はタスクだけでなく`next_id`と`revision`の整合性確認が必要です。本体とバックアップの値が確認できる場合、設計上は`next_id`を両者の最大値、`revision`を両者の最大値+1にします。整数の上限を超える場合はこの方法を使えません。本体から値を確認できない場合、過去のIDを再利用しない保証を維持できないため、推測で採番値を作らないでください。

手作業の復旧は[設計書の保存・復旧規則](detailed-design.md)を確認したうえで行い、復旧したデータを読み込めることと内容を確認してから通常操作を再開してください。

## 困ったとき

| 症状・エラー | 確認と対処 |
| --- | --- |
| コマンドが見つからない | 実行ファイルのパスを指定する。PowerShellでは`.\tque.exe`などを使用 |
| TUIが開けない | 対話端末から起動する。リダイレクトやパイプで一覧を取得するなら`ls`を使用 |
| 登録したタスクが見えない | CLIでは`ls --all`。TUIでは検索をEscで解除し、`f`で全件へ戻す。保存先も確認 |
| 親の進捗が変わらない | `[manual]`の有無と完了状態を確認。自動へ戻す場合は`-p auto` |
| `ConfigError` | 表示された設定ファイルのJSON、キー、パスを確認 |
| `InvalidInput` | タイトル、日付、進捗範囲、開始日と期日の前後関係を確認 |
| `NotFound` | `ls --all`でIDを確認。削除したIDは再利用されない |
| `CycleDetected` | 親子関係または依存関係が循環していないか確認 |
| `ReferencedTask` | 削除範囲外からの依存を確認。必要なタスクを残し、依存先を適切に編集してから再試行 |
| `RevisionConflict` | 最新データを確認し、保持された編集案を再確認して確定する |
| `LockTimeout` | 別のtqueの保存処理が終了してから再試行。待機時間は最大約5秒 |
| `CorruptData` | 本体を保全し、バックアップと復旧の説明を確認 |
| `UnsupportedSchema` | データ形式とアプリの対応を確認。形式番号を手作業で変更しない |
| `StorageFailure` | エラーの対象パス、書き込み権限、空き容量、他アプリによるファイル使用を確認 |
| `CommitUncertain` / 終了コード3 | 保存済みの可能性があるため、直ちに同じ変更を再実行せず再読込して結果を確認 |

保存結果が不明な場合、TUIは更新操作を止めます。`r`で再読込し、一覧や詳細で保存結果を確認してください。再読込しても編集内容は自動再送されません。CLIでは`ls --all`などで確認し、特に追加操作で重複登録しないようにします。再読込にも失敗する場合は、エラーと保存ファイルを保全して原因を確認します。

## シェル補完

コマンドやオプションの補完スクリプトを生成できます。以下は現在のシェルに読み込む例です。利用するシェルの例だけ実行してください。

```powershell
# PowerShell
tque completion powershell | Out-String | Invoke-Expression
```

```sh
# Bash
source <(tque completion bash)
```

```sh
# Zsh
autoload -Uz compinit
compinit
source <(tque completion zsh)
```

```fish
# Fish
tque completion fish | source
```

タスクIDの動的な候補表示には対応していません。シェルのプロファイルは自動変更しないため、永続化する場合は利用するシェルの起動設定で読み込むようにしてください。
