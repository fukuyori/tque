# tque 画面案 第1版 レビュー

このレビューは、標準入力で受け取った screen-proposal-v1.md と detailed-design.md（第5版）だけを根拠にしています。ツールは使っていません。描画や端末での確認もしていません。セル幅や端末・ライブラリの挙動に関する記述は推定で、実機での確認が必要です。ここでの提案は承認済みの仕様ではありません。

## 1. 総合評価

**一覧＋下部詳細は条件付きで妥当です。** 初版の基本構成として推奨します。

80x24 で長い日本語タイトルを扱う場合、右側詳細よりタイトル幅を確保できます。一覧のみの案と比べると、全文、開始日、依存関係を確認する場所ができます。この利点は代案より大きいと考えます。

ただし、現状のままでは実装に入れない欠落が3種類あります。

1. **通知を出す領域がない。** 第1版は、保存中・失敗・競合を「詳細欄と同じ領域」に出す案です。しかし詳細設計は、詳細欄とは別に「通知欄」を前提にしています（第8.1節の競合後の入力案、第9章のロック解放失敗）。詳細欄だけでは、選択を変えたり一覧へ戻ったりすると通知が消えます。
2. **状態ごとのキーの役割が未整理。** 検索入力中の ←→↑↓、保存中の移動、文脈行に対する操作、一覧での Enter が決まっていません。
3. **幅の計算と表示を減らす規則が未定義。** 罫線、矢印、▾ は曖昧幅の文字です。深い階層や多数の依存先があると、80桁ではタイトル列が消えるおそれがあります。

もう一つ、第1版には現行の第7.1・8.1節と合わない書式が4点あります。

- ID と枝の順序
- blocked 表示を別の行にすること
- 開始日を一覧から外すこと
- 一覧の `[manual]` が図にないこと

どれも、採用するなら仕様改訂として承認が必要です。

## 3. 推奨画面構成

以下は概念図です。セル幅は検証していません。

```text
tque | 全件 | 検索:なし | 並び:ID | 4件           保存先 D:/…/tque-data
 ID  タスク                                       進捗              期日
  1  ▾ [ ] リリース準備                           [#####.....]  50%  2026-10-23
  2    ├ [x] 設計書を確定                         [##########] 100%  2026-10-20
> 3    ├ [ ] 保存処理を実装              [manual] [#####.....]  50%  2026-10-21
  4    └ [ ] 結合テスト (blocked by #3)           [..........]   0%  2026-10-23
────────────────────────────────────────────────────────────────────────
#3 保存処理を実装
未完了  50% [manual]  開始 2026-10-19  期日 2026-10-21（今日）
親 #1 リリース準備   依存先 なし
────────────────────────────────────────────────────────────────────────
#2 を完了しました
↑↓移動 ←→階層 Space完了 e編集 x削除 /検索 ?ヘルプ q終了
```

固定部分は、見出し1行、列見出し1行、区切り線2行、詳細3行、通知1行、操作案内1行の計9行です。24行の端末なら一覧に15行使えます。

端末サイズに応じて、次のように表示を減らします。閾値は提案値で、実際に描画して調整します。

| 条件 | 表示 |
|---|---|
| 幅100以上 | `START -> DUE` を表示（第7.1節と一致） |
| 幅80〜99 | 標準（期日だけ。開始日が未来なら印） |
| 幅60〜79 | 進捗バーを外し、% だけにする |
| 幅40〜59 | 期日を詳細欄へ移す（要承認） |
| 高さ20以上 | 詳細3行 |
| 高さ14〜19 | 詳細1行（タイトルだけ） |
| 高さ10〜13 | 詳細なし。通知行と操作案内は残す |
| 幅40未満または高さ10未満 | 「端末が小さすぎます（現在 W×H、必要 40×10）」 |

構成の比較:

- **右側詳細**: 140桁以上で切り替える方式として、後回しにする。
- **一覧のみ**: 上の表の最小段階として、下部詳細の構成に含める。
- **2行表示**: 行の高さが変わる（R08）ため採用しない。

## 4. 実装前に決める事項

第1版で未確定と明記されている項目には、実害と提案を付けています。

| 事項 | 実害 | 提案 |
|---|---|---|
| 具体色 | 色の組み合わせによっては判読できない。NO_COLOR のときに情報が欠ける | 意味ごとに3色まで（選択・期限超過・依存待ち）。すべての情報に文字での表示を併記する（R10） |
| 表示を切り替える幅・高さ | 実装ごとに挙動が変わり、試験の基準がない | §3 の表を叩き台にして確定する |
| 全文を見る方法 | 200文字のタイトルが読めない | Enter（または i）で全文表示（R14） |
| 入力中の文字とカーソル移動の役割 | 誤操作が起き、検索の状態遷移が曖昧になる | R06 の状態の分け方 |
| 一覧の `[manual]` | Q02 の「行で固定を明示する」に違反する | バーの直前の固定列（R07） |
| 開始日を一覧から外すこと | 着手可能かどうかの判断材料が失われる | R17。承認が必要 |

上記以外に、初版で必ず決める事項:

- 通知行を置くことと、通知を残す規則（R02）
- 保存結果が不明なときの再確定の方式（R01）
- 保存中のキーの分類（R12）
- 削除確認画面の内容（R03）
- 曖昧幅文字の方針と ASCII の代替表示（R04）
- インデントの上限（R05）
- 1行に収める blocked の省略形（R08）
- 文脈行の扱い（R09）
- 操作したタスクが条件で非表示になったときの選択先（R11）
- 起動時エラーの画面（R19）
- 表示言語（R22）
- Cf 文字の扱い（R16）

後回しにできる改善:

- 140桁以上での右側詳細
- 検索で一致した部分の強調表示
- 折り畳んだ親に隠れている子の件数（`▸ (+5)`）
- 完了した親に未完了の子が残っているときの件数表示
- +Nd を入力したときの日付プレビュー
- 最終読込時刻の表示
- 保存中表示の遅延（R28）
- 全角と半角を区別しない検索（Unicode 正規化をしない方針との調整が必要）

実端末で確認が必要な項目（未検証）:

- 曖昧幅文字と絵文字の ZWJ 結合列の表示幅
- IME で変換中の文字を即時検索がどう扱うか
- NO_COLOR のときの反転属性の表示
- 3 OS の端末での ▾・罫線・矢印の表示
