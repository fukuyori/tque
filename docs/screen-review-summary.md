# 画面案レビューの比較

日付: 2026-10-21

対象: [画面案 第1版](screen-proposal-v1.md)、詳細設計第5版。

## 結果

両者とも「一覧＋下部詳細」を初版の基本構成として推奨。ただし、具体的な表示・操作規則の確定が必要という評価。

件数と重要度は各レビュー元の分類であり、採用件数や欠陥の確定件数ではない。

## 共通して具体化を求められた点

| 論点 | Claude Code | Antigravity | ロクの評価 |
| --- | --- | --- | --- |
| 検索入力中と検索適用後の一覧のキー分離 | R06 | RV-01 | 具体化が必要。入力中の左右はテキストカーソル、Spaceは文字入力という方向が妥当。上下で選択を動かすかは未確定 |
| 狭い画面・深い階層でタイトル幅を確保 | R05ほか | RV-02・09 | 必要。固定閾値だけでなくID・階層・タグ込みのセル配分を確認する。提案の閾値は未検証 |
| 長いタイトル・依存先の全文閲覧 | R14・18 | RV-03 | 必要。下部の固定行だけで全文を保証できない。読み取り専用の詳細画面は有力候補 |
| CLIとTUIの表示書式を分離 | R07・08・17 | RV-04 | 妥当。開始日、IDと枝の順序、manual、依存警告の変更点を明示して設計へ反映する必要がある |
| 削除確認・競合・保存結果不明の具体表示 | R01・03・13 | RV-05・07 | 必要。保存結果不明を通常の入力エラーや未保存と混同しない |
| 色なしで期日・状態を識別 | R10 | RV-11 | 妥当。色とは独立した文字表示と、明暗背景での判読性を確認する |

Claude CodeのR02（詳細欄と別の通知領域）は特に有用。選択変更で重大な通知や保持した入力案が失われない表示・閲覧方法を決めたい。R11（完了後にフィルタから消える行の選択移動）、R20（検索なしではEscによる検索解除を案内しない）も具体的な操作改善。

## 改善案をそのまま採用しない点

- Claude Code R01の「元のexpectedRevisionで再確定」は保存プロトコルの追加提案。画面レビューだけで採用せず、結果不明時に再読込して保存内容を確認する現行方針と照合する。古いrevisionによる拒否だけでは、利用者が結果を判断する表示は完成しない。
- Antigravity RV-02のmanual短縮は、現行の一覧での`[manual]`明示からの変更。さらに提案図では手動進捗と今日期日に同じ`*`を使っており、区別を再検討する。
- Antigravityの画面例には、依存先IDに対応するタイトルを取り違えた説明（#3を「結合テスト」とする箇所）がある。原文を保存し、画面仕様には転記しない。
- Antigravity RV-08にある検索文字列「最大200文字」は現行設計で確定していない。タイトル上限と検索入力の上限を混同しない。
- Antigravity RV-11の具体的なANSI灰色だけでコントラストが保証されるわけではない。配色と実端末の背景を合わせて確認する。
- Claude Code R16の文字分類は別途確認が必要。Cfの一律拒否は、保持する方針の絵文字のZWJなどに影響するため、そのまま採用しない。
- 通知から`?`で詳細を開く案は、既存の`?`ヘルプとの役割整理が必要。
- 最小画面サイズ、インデント上限、列幅、全文閲覧キーは両者で異なる提案値。まだ実機で確認しておらず、合意済み仕様としない。

利用者から「再検討に関しては、一旦保留し、推奨で進める」と指示された。ツリー一覧＋下部詳細、独立した通知欄、読み取り専用の全文詳細画面を採用し、[詳細設計](detailed-design.md)第8.3節へ反映した。第8.4節に再検討項目を保留として記録した。上の「作業範囲」はレビュー完了時点の記録であり、今回の設計改訂とは時点が異なる。

個別の改善案・寸法・キー割当を一括採用したものではない。原文と画面案第1版は変更せず、実装・描画検証は未実施。
