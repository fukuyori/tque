# tque 画面案 第1版（レビュー対象）

作成日: 2026-10-21

位置付け: 会話で提示した画面案をレビュー用に固定したもの。未確定の提案であり、現行の詳細設計第5版を変更しない。コードや描画結果は存在しない。

## 1. 構成の比較

- 一覧のみ: 多くのタスクを表示できるが、日付・依存関係を含めると横長になる。小さい画面向き。
- 一覧＋下部詳細（推奨）: タイトルの横幅を維持し、選択タスクの全文・開始日・依存関係を確認できる。
- 一覧＋右側詳細: 大画面向きだが、日本語の長いタイトルが省略されやすい。初版では見送る提案。

## 2. 標準画面

以下は概念図で、端末セル幅を検証した描画ではない。

```text
tque                            保存先: D:/tque-data
表示: 全件    検索: なし    並び: ID    一致: 4件

   ID  タスク                       進捗              期日
   #1  ▾ [ ] リリース準備           [#####.....]  50%  2026-10-23
   #2    ├ [x] 設計書を確定         [##########] 100%  2026-10-20
 > #3    ├ [ ] 保存処理を実装       [#####.....]  50%  2026-10-21
   #4    └ [ ] 結合テスト           [..........]   0%  2026-10-23
               (blocked by #3)

────────────────────────────────────────────────────────────
#3 保存処理を実装
進捗: 50% [manual]   状態: 未完了
開始: 2026-10-19     期日: 2026-10-21（今日）
親: #1 リリース準備  依存先: なし
────────────────────────────────────────────────────────────
↑↓ 移動  ←→ 階層  Space 完了切替  a 追加  / 検索  ? ヘルプ
```

図では省略しているが、手動進捗の行には一覧でも `[manual]` を表示する意図。図との不一致もレビュー対象。

表示ルールの提案:

- タイトル列を可変幅、進捗と期日を固定幅にする。省略タイトルは下部で全文確認する。
- 選択は背景色と `>` の両方で示す。NO_COLOR時も識別できる。
- 完了は `[x]`、進捗は数値とバー、依存待ちは文字で別々に示す。todoで100%も許可、blockedでも編集・完了可能という既存仕様を維持する。
- 色は選択、期限超過、依存待ちを中心に使用。完了行は控えめにするが判読性を保つ。具体色は未定。
- 一覧に期日、下部詳細に開始日を表示する。これは現行詳細設計第7.1・8.1節からの変更提案であり、未承認。
- ID、階層の枝、開閉印を表示する。

## 3. 検索と編集

```text
表示: 未完了    検索: 保存    並び: 期日    一致: 1件

   #1  ▾ [ ] リリース準備 [context]
 > #3    └ [ ] 保存処理を実装 [manual] ...

検索: 保存_
Enter 検索を確定    Esc 検索開始前に戻す
```

検索中も一覧を残す。文脈用祖先は一致件数に含めず、親の進捗は全子から算出する。検索中の左右は親子移動のみ、検索条件解除後は通常の折り畳み状態を復元するという既存仕様に従う。ただし入力中の文字・カーソル移動との役割整理はレビューで確認する。

属性編集では下部詳細を入力欄に置き換え、一覧の選択対象を残す。

```text
#3 の期日を編集
期日: 2026-10-21_
YYYY-MM-DD / today / +3d    空欄で解除
Enter 保存    Esc 取消
```

保存中・保存失敗・競合も同じ領域で明示し、失敗した入力は保持する。既存設計の確定操作ごとの保存、競合時の自動再送禁止、CommitUncertainの区別を維持する。

## 4. 小さい画面と初回起動

- 幅不足なら進捗バーを数値だけにしてタイトル幅を確保する提案。
- 高さ不足なら詳細欄を縮め、主要操作案内を残す。切替幅・高さ、詳細の全文閲覧方法は未確定。
- 全件が空なら「タスクはまだありません。a で追加」。
- 検索結果が空なら「一致するタスクがありません」と条件解除方法を表示する。
- 初版ではカレンダーと常設サイドバーを追加しない提案。

## 5. レビュー条件

一覧＋下部詳細を無条件に採用せず、代案との比較も求める。200コードポイントのタイトル、深い階層、長い保存パス、多数の依存先、日本語・結合文字・絵文字、色なし、80x24および小さな端末、フィルタ下の文脈行、削除確認とヘルプ、保存結果不明を検討する。

利用者の指示はレビュー依頼であり、レビュー回答自体は仕様の確定・修正許可ではない。
