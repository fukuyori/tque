# `tque` 画面案（第1版）独立レビュー

対象資料：`screen-proposal-v1.md`（画面案 第1版）、`detailed-design.md`（詳細設計書 第5版）
前提：提示された資料のみに基づく机上レビューであり、実機検証・コード実装・外部ライブラリの挙動確認は行っていません。画面案の提案内容は未承認案として扱います。

---

## 1. 総合評価

**「一覧＋下部詳細」の基本構成は、日本語の長いタイトルや階層構造を扱うTUIとして妥当性が高い**と評価します。一覧のみでは開始日・多数の依存先・200コードポイントのタイトルを80x24端末に収められず、右側詳細では2カラム分割により日本語タイトルが10〜15文字程度で省略され一覧性が崩壊するためです。

一方で、**現行詳細設計（第5版）との不整合や、80桁幅でのセル計算破綻、キーボード操作（特に検索入力中の左右キーや下部詳細のスクロール）の衝突、異常系（保存結果不明・競合時・削除拒否時）の表示仕様不足**が見られます。とくに一覧行の固定列幅の合計が80x24環境でタイトル領域を圧迫する点と、下部詳細ペインが固定行数では200文字タイトルや多数の依存先を表示しきれない点は、実装前に仕様を確定させる必要があります。

## 2. 重要度順の指摘表

重要度は **高**（仕様矛盾、誤操作・データ誤認、80x24での表示破綻、異常系の判断不能）、**中**（境界条件での表示崩れ、未確定項目の具体化不足、操作性の阻害）、**低**（表記揺れ、軽微な視認性改善）の3段階で分類しています。

| **A. 一覧のみ** | ・縦方向の表示行数を最大化できる（24行中20行近くをタスク行に使える）。 | ・開始日、期日、進捗、依存先ID列、手動モードを1行に並べると80桁ではタイトル幅が皆無になる。<br>・2行折り返しにすると行の高さが不揃いになり一覧性が低下する。 | 不採用（極小高さ時の一時縮退としては有効） |
| **B. 一覧＋下部詳細（画面案推奨）** | ・**一覧の横幅をタイトル・進捗・期日の3要素に集中できる**（日本語タイトルに全角15〜20文字程度を確保可能）。<br>・選択中タスクの開始日、親タスク名、複数の依存先、省略されたタイトル全文を下部で確実に確認できる。<br>・属性編集や削除確認、保存エラー通知を下部ペインの差し替えで一貫して表現できる（画面遷移の迷いが少ない）。 | ・縦方向を6〜7行消費するため、24行端末での一覧表示行数が13〜14行程度になる。<br>・極端に長いタイトル（200文字）では下部詳細内でもさらなる展開・スクロール手段が必要。 | **推奨（採用）** |
| **C. 一覧＋右側詳細（2カラム）** | ・ワイド画面（120〜160桁以上）では縦の一覧行数と詳細の情報量を両立できる。 | ・80桁端末で左右分割（例：左45桁＋右35桁）すると、左ペインの固定列（ID・階層・チェック・進捗・期日）だけで40桁以上を消費し、**日本語タイトルが1文字も表示できなくなる**。 | 初版では不採用（将来120桁以上でのみ自動切替する拡張候補） |

### 3.2 推奨する標準画面レイアウト（80x24基準・修正案）

```text
tque                                         保存先: .../tque-data
表示: 全件   検索: なし   並び: ID   一致: 4件
────────────────────────────────────────────────────────────────────────────────
   ID   タスク                             進捗            期日
   #1   ▾ [ ] リリース準備                 [#####.....]  50% 2026-10-23
   #2     ├ [x] 設計書を確定               [##########] 100% 2026-10-20
 > #3     ├ [ ] 保存処理を実装             [#####.....] 50%* 2026-10-21*
   #4     └ [ ] 結合テスト                 [..........]   0% 2026-10-23 [dep]
────────────────────────────────────────────────────────────────────────────────
#3 保存処理を実装
状態: 未完了          進捗: 50% [manual]     開始: 2026-10-19   期日: 2026-10-21 (今日)
親  : #1 リリース準備                        依存先: なし (着手可能)
────────────────────────────────────────────────────────────────────────────────
↑↓/←→:移動 Space:完了 a/A:追加 e/s/d/p/l:編集 x:削除 /:検索 f:絞込 ?:ヘルプ q:終了
```

**修正のポイント：**
1. **1行1タスクの厳守**：`#4` の `(blocked by #3)` を2行目に折り返さず、一覧行末の短い印（`[dep]` 等）または状況表示に留め、下部詳細の `依存先: #3 結合テスト (未完了: #3)` で詳細に出すことで、一覧の行高を1行に統一。
2. **`[manual]` の省スペース化**：一覧の進捗欄では `50%*` のように1文字で手動固定を示し、下部詳細で `50% [manual]` と明記することでタイトル幅を8セル拡大。
3. **`NO_COLOR` 対応の日付・状態記号**：今日期日に `*`、期限超過に `!` を付与し、色なし環境でも判別可能に統一。

## 4. 実装前に決める事項（初版確定事項と後回しにできる改善）

### 4.1 初版（実装前）に確定すべき事項

1. **詳細設計第7.1節・8.1節との書式整合（RV-04）**
   - CLIの `ls` 出力形式（第7.1節）は従来の1行全出力を維持しつつ、TUIの一覧行は「開始日・詳細な `blocked by` リストを下部詳細へ移す」ことを詳細設計第8.1節の正式仕様として承認・反映するかどうか。
2. **検索入力モード中のキーバインド分離（RV-01）**
   - `/` で検索入力中の `←` `→` `Space` を「文字入力・テキストカーソル操作」とし、`Enter` 確定後に「一覧での親子移動・完了切替」に戻す2段階操作で確定するか。
3. **80桁での列幅配分と縮退閾値（RV-02, RV-09）**
   - 最小端末サイズ（例：40x12）、進捗バーを非表示にする幅閾値（例：80桁未満またはタイトル残り幅16セル未満）、下部詳細を縮小・非表示にする高さ閾値（例：20行未満で縮小、15行未満で非表示）。
4. **下部詳細に収まらない長文（200文字タイトル・多数依存）の閲覧方法（RV-03）**
   - 下部詳細の最大行数（例：6行）と、省略された全文を見るためのキー（例：`v` または `Enter` で全文表示ポップアップ／詳細スクロールモード）。
5. **異常系（`CommitUncertain` / `RevisionConflict` / `ReferencedTask`）の下部ペイン文言とキー操作（RV-05, RV-07）**
   - とくに `CommitUncertain` 発生時に `Enter` 再送を禁止し `r`（再読込）へ誘導する状態遷移の確定。

### 4.2 後回し（第2版以降）にできる改善

1. **大画面（120桁以上）での右側詳細（2カラム）自動切替**
   - 初版は「一覧＋下部詳細」の1構成に絞ることで描画・リサイズ計算の複雑化とバグを防げる。
2. **カレンダービューや常設サイドバー（画面案4節の通り見送りで妥当）**
3. **色テーマのカスタマイズ設定**
   - 初版は「標準ANSIカラー（16色または適応色）＋ `NO_COLOR` 対応」の固定パレットのみで十分であり、設定ファイルへの色定義追加は不要。
4. **折り畳み行における子孫の集計バッジ（期限超過件数などの高度なサマリ表示）**
   - 初版は開閉印（`▾`/`▸`）と下部詳細での子件数表示があれば実用上問題ない。
