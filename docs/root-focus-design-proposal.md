# 起点タスク指定による絞り込み表示: 詳細設計改訂案

状態: 利用者の実装指示により承認。詳細設計第10版（Q21、第7.3・8.6節）へ反映し実装済み（issue #1）。起動時の折り畳みは詳細設計第12版で「起点と子孫をすべて展開」に変更（第8.6節）。  
作成日: 2026-10-25  
対象: [詳細設計書](detailed-design.md) 第8版（作成時）

## 1. 目的と方針

複数プロジェクトを、保存形式を変えずに既存の親子関係で管理する。

- 最上位にプロジェクト名のタスクを作り、その子孫としてプロジェクトのタスクを置く。
- 起動オプション `--root` で任意のタスク（IDまたはタイトル）を起点に指定し、その起点と子孫だけを表示する。
- 起点はルートタスクに限らない。下位のタスクを指定した場合は、そのタスクを深さ0として下位レベルから表示する。

[複数プロジェクト設計案](multi-project-design-proposal.md)（schema 4、Project内ID、`project_id`）は本案で置き換える。TUIの複数選択と一括移動は本案の対象外とし、別途検討する。

### 1.1 本案で採用した選択

利用者が「推奨案で」と指示した項目。推奨を明示していなかった項目は、本案作成時に選んだ値を「※」で示す。

| 項目 | 採用 |
| --- | --- |
| 指定対象 | 任意のタスク。下位タスク指定時は下位レベルから表示 |
| 名前とID | 同じオプションで受け付ける。複数候補はTUIで選択 |
| オプション名 | ※ `--root` |
| 名前の一致条件 | 完全一致。前後空白を除去し、大文字小文字を区別しない |
| 数値の値 | IDとタイトルの両方を候補にする |
| 完了済みタスク | 候補に含め、`[x]`で示す |
| 選択画面のEsc | ※ 全体表示で開く |
| CLIの`ls` | ※ 同じオプションを提供。複数候補は候補一覧を示してエラー |
| 起点の行 | ※ 一覧の先頭に深さ0で表示し、通常のタスクとして操作可能。祖先の経路はヘッダーに表示 |
| 空行 | ※ 起点表示では区切らない（ルートが1つのため） |
| 起点の削除 | 通知して全体表示に戻る |

## 2. 保存形式

変更しない。schema 3を維持し、移行・バックアップ・旧版との互換性に影響しない。起点の指定は起動ごとのもので、設定にもデータにも保存しない。

## 3. 起点の解決

### 3.1 照合

`--root VALUE` の値を次の規則で照合し、候補集合を作る。

1. 前後の空白を除去する。空文字、制御文字を含む値は引数エラー（終了コード2）とする。
2. 値が第5.1節のID規則で正の整数として解釈できれば、そのIDのタスクを候補に加える。
3. タイトルが値と一致するタスクを候補に加える。一致判定はGoの`strings.EqualFold`相当で、Unicode正規化はしない。タイトルは保存時に前後空白が除去済みである。
4. 同じタスクが2と3の両方で一致した場合は1件として扱う。
5. 完了済みタスクも候補に含める。

部分一致は使わない。`/`による検索（部分一致）とは目的が異なり、候補が過剰になるため。

### 3.2 候補数による分岐

| 候補数 | TUI | `ls` |
| --- | --- | --- |
| 0 | TUIを起動せずNotFound（終了コード1）。実装のメッセージは`no task matches --root "VALUE"` | 同左 |
| 1 | その起点で一覧を開く | その起点で一覧を出力 |
| 2以上 | 起点選択画面を表示（第3.3節） | InvalidInput（終了コード1）。stderrに候補をID・経路付きで列挙し、IDでの再指定を促す。stdoutには出力しない |

照合は読込で取得したDocumentに対して行い、更新ロックを保持したまま利用者の選択を待たない（第3章のロック方針）。対話端末の確認は従来どおりデータ読込より前に行う。

### 3.3 起点選択画面（TUI）

```text
起点を選択: "設計"  3件
> #12 [ ] ブログ > 設計            40%
  #31 [ ] 仕事 > 新機能 > 設計      10%
  #45 [x] 設計                    100%
↑↓:選択  Enter:開く  Esc:全体表示で開く  q:終了
```

- 各行にID、状態、祖先からの経路、表示進捗を示す。並びはID昇順。
- 経路が幅に収まらない場合は、先頭側の祖先を`..`で省略し、候補タスク自身のタイトルを優先して残す。
- 上下/j/k・PageUp/PageDownで選択、Enterで開く、Escで起点なしの全体表示を開く、q/Ctrl+Cで終了する。
- 画面サイズの下限（40×10）と、サイズ不足時の表示は一覧と同じ。
- この画面ではデータを変更しない。`r`による再読込は初版では受け付けない。

## 4. TUIの起点表示

### 4.1 起点の保持

- 起点はプロセス内で固定内部ID（InternalID）で保持する。表示用IDの変更（`i`、CLIのrenumber）には追随する。
- 起点のタスクが別の親の下へ移された場合も、起点として有効なまま表示を続ける。
- 再読込・保存成功・競合時の再読込で起点が存在しない場合は、起点を解除して全体表示へ切り替え、`起点 #N は削除されたため全体表示に切り替えました`と通知する。TUIで起点自身を削除した場合も同じ。
- 初版ではTUI内で起点を変更・解除するキーを設けない。変更は再起動で行う。

### 4.2 表示範囲とツリー

| 対象 | 規則 |
| --- | --- |
| 表示対象 | 起点とその全子孫。検索・表示条件（`f`）・並び（`o`）はこの範囲に適用する |
| 一致件数 | 範囲内で条件に一致したタスク数。起点自身も一致すれば数える |
| 文脈行 | 一致タスクの祖先を`[context]`として残す処理は起点で止め、起点より上の祖先は表示しない |
| 起点の行 | 一覧の先頭に深さ0で表示する。条件に一致しない場合は従来どおり`[context]` |
| 深さ・インデント・階層色 | 起点からの相対深さで計算する。全体表示と色が異なることを許容する |
| 枝線 | 表示行の中に親がない行をツリーの起点として扱う。起点の行には枝線を付けない |
| 空行 | ルートが切り替わる位置に入れる従来の規則を「表示行に親がない行への切り替わり」に一般化する。起点表示では起点が1つのため空行は出ない |
| 起動時の折り畳み | 起動時に子を持つタスクをすべて折り畳む現行規則（詳細設計第8.2節）のうち、起点だけは展開した状態で開き、起点の子以下は折り畳む |
| 進捗・依存警告 | 文書全体から計算する。範囲外の子・依存先も従来どおり反映する |
| ID列幅 | 従来どおり文書全体の最大IDで決める |

### 4.3 操作の変更

| 操作 | 起点表示での動作 |
| --- | --- |
| `a` | 起点の子として追加する。入力欄のラベルは`#N の子を追加（起点）` |
| 左 | 起点の行では、展開中なら折り畳み、それ以外は無変更。範囲外の親へ選択を移さない |
| `x`/Delete | 従来どおり件数付きで確認する。起点を削除した場合は第4.1節に従い全体表示へ戻る |
| Space | 従来どおり。起点の完了には全子孫の完了が必要（現行実装の規則） |
| `i` | 従来どおり文書全体の番号を変更する。範囲外のタスクの番号も変わり得ることを入力ヒントで示す（既存の注記を維持） |
| `l` | 範囲外のIDも依存先に指定できる |
| その他 | 変更なし |

全体表示（起点なし）の動作は従来と同じ。

### 4.4 ヘッダーとヘルプ

- ヘッダー1行目を`tque  起点: 仕事 > 新機能 > 設計 (#31)  保存先: PATH`とする。幅が不足する場合は保存先を先に省略し、次に経路の先頭側の祖先を`..`で省略する。起点のタイトルとIDは最後まで残す。
- 起点なしでは従来どおり`tque  保存先: PATH`。
- `?`ヘルプの末尾に、起点の全経路とID、保存先、最新の通知を表示する。
- ヘッダーの行数は変えず、一覧の高さに影響させない。

## 5. CLI

| 指定 | 動作 |
| --- | --- |
| `tque --root VALUE` / `tque --tui --root VALUE` | 起点を指定してTUIを起動する |
| `tque ls --root VALUE [既存フラグ]` | 起点と子孫に限定して一覧する。`--tree`では起点を先頭・深さ0で表示し、文脈行は起点で止める。JSONの形式は変えない |
| 上記以外のサブコマンドとの併用 | 引数エラー（終了コード2） |

- `--root`はルートコマンドと`ls`のローカルフラグとする。help/version/completionは従来どおり設定・データを読み込まない。
- `add`・`edit`等はIDで対象を直接指定するため、範囲の概念を持ち込まない。
- 補完はデータを読まない方針を維持し、`--root`の値を補完しない。

## 6. 実装上の変更点（参考）

実装は未承認。現行コードから見込まれる変更箇所を示す。

- `engine.Query`に起点ID（0は指定なし）を追加する。`Select`は候補を起点と子孫に限定し、祖先の追加を起点で止め、起点からツリーを構築して深さ0とする（`internal/engine/query.go`）。
- `TreePrefixes`・`TreeGap`の起点判定を「親がない行」から「表示行に親がない行」へ一般化する（`internal/engine/tree.go`）。全体表示での結果は変わらない。
- 起点の照合関数を追加する（ID・タイトルの候補集合、経路文字列）。CLIとTUIで共有する。
- TUI: 起点のInternalID保持、起点選択画面のモード、`a`の親設定、左キーの制限、ヘッダー、起点消失時の処理（`internal/tui`）。
- `cmd`: `--root`フラグ、併用検査、`ls`への受け渡し、RunTUIへの起点値の受け渡し（`cmd/root.go`）。

## 8. 必要な検証

- 照合: ID一致、タイトル完全一致（大文字小文字違い、前後空白）、数値タイトルとIDの同時一致、同一タスクの重複排除、0件、空値・制御文字。
- 起点選択画面: 経路表示と省略、Enter・Esc（全体表示）・q、40×10での描画、データ非変更。
- 下位タスクを起点にした表示: 起点が深さ0、枝線なし、空行なし、範囲外の祖先が文脈行に出ない、相対深さでの色。
- 範囲内の検索・表示条件・並び、一致件数、文脈行としての起点。
- `a`が起点の子として追加されること、左キーが範囲外へ出ないこと。
- 起点の番号変更（TUI・CLI）への追随、親の変更後も表示継続、削除・再読込での全体表示への切替と通知。
- 範囲外の子を含む進捗、範囲外の依存先の`!dep`表示。
- `ls --root`の通常・`--tree`・`--json`、複数候補時のstderr列挙と終了コード、他サブコマンドとの併用拒否、help/version/completionでの非読込。
- 起点なしの全体表示・既存CLIの出力が従来と一致すること。

## 9. 対象外

- TUIの複数選択と一括移動（別途検討）。
- TUI内での起点の変更・解除。
- プロジェクトをまたぐ依存の制限（境界を持たないため許可）。
- 保存形式の変更、プロジェクト専用のデータ項目。
- 現行実装と詳細設計の既存差（undone後の進捗、完了時のmode、親の完了制約、並び順の種類、キー表の未記載）の整理。本案とは別に基準を決める。
