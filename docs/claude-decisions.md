# tque 未確定事項の決定（第2版への回答）

決めた範囲は製品仕様までです。OSの動作や依存ライブラリについての記述は、ここで決めたものではなく、第5節で実機確認や一次資料の確認に回しています。

## (1) Q01〜Q16の採否と最終仕様

第1版レビューへの5つの対応（auto切替時の進捗保持、done・undoneでの値保持、親子と依存の別検査、読込・更新とも排他ロック、置換の自動再試行なし）は、草案の各節で互いに矛盾していません。第4節は、それ以外に見つかった細部の不整合への置換文です。

| ID | 採否 | 最終仕様（草案からの変更点のみ追記） | 理由 |
|---|---|---|---|
| Q01 | 採用 | `next_id`を持つ。削除しても戻さない | 欠番を再利用しないという基本設計の意図を守れる唯一の方式 |
| Q02 | 採用 | `progress_mode`を持つ。数値を指定するとmanual、`auto`で固定を解除。切替では保存値を保持 | 固定の解除方法をはっきりさせ、保存値も失わない |
| Q03 | 採用 | 直下の子の表示進捗を同じ重みで平均し、切り捨てる | 多段階でも再帰的に計算でき、実装が軽い |
| Q04 | 採用 | blockedでも進捗編集と完了は許可し、警告だけ出す | 基本設計の「警告表示」に合わせる |
| Q05 | 採用 | 削除対象の外から依存されていれば削除を拒否し、参照元IDを表示する | 参照切れを残さない |
| Q06 | 採用 | undoneは保存進捗とmodeを維持する。todoで100%も許容 | 情報を失わず、操作が単純 |
| Q07 | 採用 | statusは明示操作でだけ変わる。親子間で伝播させない | 予測しやすい |
| Q08 | 採用 | 親子は包含、依存は先行条件として、別々に循環検査する。結合したときだけ生じる循環は許可 | 親子に完了順序の意味を持たせないため |
| Q09 | 採用 | `ls`はtodoのみをID昇順で表示、`--all`でdoneも含める。TUIは全件をツリー表示 | キューとして使いやすい |
| Q10 | 決定 | (2)を参照 | — |
| Q11 | 採用＋具体化 | タイトルは最大200コードポイント（rune）で、不正なUTF-8は拒否。`+Nd`のNは0〜36500で、結果が9999-12-31を超えれば拒否。それ以外は第5.1節のとおり | 境界値を試験できる形にする |
| Q12 | 採用 | revisionで楽観的に競合を検出する。自動再送はしない | 更新が消えるのを防ぐ |
| Q13 | 採用 | 確定操作ごとに保存する。終了時は未確定入力を破棄し、子孫削除は件数付きで確認する | 基本設計の「自動保存して終了」を実質的に満たす |
| Q14 | 採用 | 依存先に一つでもtodoがあればblocked。doneのタスクにも同じ判定を表示 | 判定を一つに統一する |
| Q15 | 採用＋修正 | 第7・8章のとおり。`r`/`p`キーも採用。done中の`+`/`-`は第4節の修正を適用 | 公開仕様の確定 |
| Q16 | 採用 | ロック待ちは5秒でタイムアウト。手動復旧の手順を用意し、保存先の変更機能は付けない | 軽量さを優先 |

## (2) Q10と配布

- **Goの方針**
  - ビルドには、実装開始時点の最新安定版Goを使います。
  - `go.mod`の`go`行は、採用した依存ライブラリが要求する最小値にします。
  - 「Go 1.22でもビルドできること」は保証しません。基本設計の「1.22+」は下限の目安と読み替えます。
  - `toolchain`行は記載し、ビルドで使った版をリリースノートに記録します。
- **モジュールパス**: `tque`（ドメインなしのローカル用パス）
  - 配布はインストーラーで行い、`go install`による公開取得は対象外です。
  - 所有権を確認できる公開リポジトリができた時点で、そのURLへ一括で置換します。
- **本体ライセンス**: MIT
  - 依存ライブラリのライセンスとの両立は採用前に確認します（第5節）。
  - 著作権者の表記は、実装時に利用者の名義を記入します。
- **対応OS/CPU**
  - 初版で配布するのは`windows/amd64`のみで、インストーラーと署名の対象もこれだけです。
  - `windows/arm64`、`linux/amd64`、`darwin/arm64`はクロスビルドとユニットテストだけ行い、配布しません。
  - これらは実機で確認してから配布対象に加えます。
- **初回バージョン**: `0.1.0`（SemVer）
  - リポジトリ直下の`VERSION`ファイルを唯一の正とします。
  - バイナリには`-ldflags -X`で、`.iss`にはISCCの`/D`で注入します。
  - `docs/version-update-checklist.md`には`VERSION`だけを更新対象として記載します。
- **インストール**: ユーザー単位
  - 管理者権限は不要（`PrivilegesRequired=lowest`）で、インストール先は`%LOCALAPPDATA%\Programs\tque`です。
  - ユーザーのPATH（HKCU）にインストール先を1件だけ追加し、重複追加しません。
  - アンインストール時は、インストーラーが追加したPATH項目だけを削除します。`~/.tque`は削除しません。

## (3) タイトル長と性能目標

- **タイトル長**: 最大200コードポイント。CLIとTUIで同じ規則にし、TUIの入力欄も同じ上限で止めます。
- **想定規模**: 最大10,000タスク、親子の深さ1,000、依存の辺20,000まで。それを超える件数は動作しても目標の対象外です。
- **計測条件**: Windows 11 x64の実機、ローカルSSD、2回目以降の起動。p95で記録します。

| 項目 | 1,000件 | 10,000件 |
|---|---|---|
| `ls`（起動から出力完了まで） | 200ms以内 | 1秒以内 |
| `add`/`edit`（ロック・同期を含む） | 300ms以内 | 1.5秒以内 |
| TUI起動から初回描画まで | 300ms以内 | 1秒以内 |
| TUIのカーソル移動（保存なし） | 50ms以内 | 50ms以内（描画は表示行だけ） |

- 深さ1,000でスタックがあふれないことも合格条件にします。
- 目標に届かない場合は、原因を記録したうえで再設計を検討します。記録なしに目標値だけを下げることはしません。

## (5) 外部資料・実機確認が必要な技術検証

1. **Windowsでの置換**
   - `os.Rename`の実装（`MoveFileEx`の置換フラグか`ReplaceFile`か）と、既存ファイルを上書きできるか。
   - 共有違反（ウイルス対策ソフトや検索インデクサーがファイルを開いている場合）や、読取専用属性があるときの本体の状態。
   - これは「置換を自動再試行しない」判断を維持できるかの根拠になります。
2. **永続化の範囲**: `Sync`（`FlushFileBuffers`）の効果と、置換後のディレクトリ永続化がWindowsで可能か・必要か。
3. **ロック**
   - Windowsの`LockFileEx`とUnixの`flock`、またはそれらを包むライブラリの選定。
   - プロセスを強制終了したときにロックが解放されるか、ポーリング間隔をどうするか（提案は50ms）。
4. **依存ライブラリ**: Cobra、Bubble Tea、Lip Gloss、`golang.org/x/sys`、表示幅計算ライブラリの採用バージョン、要求Go版、ライセンス、推移依存の著作権表示。
5. **Bubble Teaの実端末動作**（Windows Terminalと従来のコンソール）
   - 日本語IMEでの入力、Shift+A、Delete、`+`/`-`（日本語配列）、リサイズ、終了後に端末が元に戻るか。
   - `NO_COLOR`の扱い。
6. **文字表示**: UTF-8出力とコードページの関係、全角・結合文字・絵文字の表示幅。
7. **パス**: `os.UserHomeDir`が日本語や空白を含むパスで正しく動くか。
8. **Inno Setup**
   - `PrivilegesRequired=lowest`でHKCUのPATHを編集・削除できるか、`ChangesEnvironment`で変更が反映されるか。
   - `SignTool`とアンインストーラーへの署名（`SignedUninstaller`）の方法、将来arm64に対応する場合のアーキテクチャ指定。
9. **署名**: `CODESIGN_CERT`の形式（PFXのパス、拇印など）、使う署名ツール、タイムスタンプサーバー、既存スクリプトとの互換性、SmartScreenでの表示。
10. **バージョン注入**: `-ldflags -X`とISCCの`/D`による注入を実ビルドで確認。
