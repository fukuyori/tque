## 1. 目的と適用範囲

タイトル、親子関係、依存関係、開始日、期日、進捗を管理するGo製の単一バイナリを設計する。CLIとTUIは同じ業務ロジックと保存処理を使用する。本文、クラウド同期、複数ユーザー共有、通知、繰り返しタスクは今回の基本設計の対象に含まれない。

本書の「確定」は基本設計または利用者の作業ルールを根拠とする。「提案」は設計者による案であり、利用者の承認を意味しない。未決事項は第2章に集約する。外部ライブラリの具体的API、採用バージョン、OS固有の保証は未検証であり、実装前に一次資料と実機で確認する。

今回の成果物は設計書とClaude Codeのレビュー記録。アプリ実装、依存取得、ビルド、パッケージ作成、Git操作は行わない。

## 2. 決定が必要な事項

以下の提案に依存する実装は、回答を得るまで確定させない。

| ID | 基本設計の不足・矛盾 | 提案 | 影響 |
| --- | --- | --- | --- |
| Q01 | `max(ID)+1`と「欠番再利用しない」は最大ID削除時に両立しない | 保存データに`next_id`を持ち、削除しても戻さない | JSON形式、採番 |
| Q02 | 手動進捗固定の識別・解除方法がない | `progress_mode: auto/manual`を追加し、`edit -p auto`で解除する | CLI、JSON、TUI |
| Q03 | 子の平均が直下の子か全末端か不明 | 直下の子の表示進捗を等重みで平均し、切り捨てる | 多段階WBSの値 |
| Q04 | blocked時の編集・完了禁止は記載なし | 警告表示のみ。進捗編集と完了は許可する | 操作制限 |
| Q05 | 他タスクから依存される対象の削除規則がない | 削除集合外から参照されている場合は拒否する。依存を明示解除してから削除 | rm、cascade |
| Q06 | undone後の進捗が未定義 | todoへ戻し、完了日時を消去。保存進捗100と進捗モードは維持する | todoで100%を許容 |
| Q07 | 親のdoneと未完了の子、100%とstatusの関係が未定義 | statusは明示操作だけで変更。親の完了は子へ伝播せず、doneの表示進捗は100 | 親子整合性、表示 |
| Q08 | 親子と依存を混ぜた閉路の意味が不明 | 子→親とタスク→依存先を合わせた有向グラフでも閉路を拒否する | 親が子に依存する指定も拒否 |
| Q09 | 一覧の既定フィルタ・順序が未定義 | lsはtodoのみ、--allでdoneも表示。ID昇順。TUIは全件のツリー | 表示 |
| Q10 | Go 1.22+の意図、対応OS、モジュールパス、ライセンスが未確定 | Windowsを優先検証。Go最低版・他OSの配布・モジュールパス・本体ライセンスは利用者に確認 | 依存選定、配布 |
| Q11 | 日付の大小、タイトル空白、入力構文の細部が未定義 | 第5章の入力規則を採用する | CLI/TUI共通 |
| Q12 | 並行編集時の方針が未定義 | TUIは編集開始時のrevisionを送信し、競合したら再読込して再操作する | 保存形式、操作体験 |

Q04の根拠は基本設計が警告表示のみを明記していることであり、操作許可が確定したわけではない。Q08は親子循環と依存循環を別々に検査する方式より厳しい。両者の意味の違いを確認してから採用する。

## 3. 構成と責務

| パッケージ | 責務 | 禁止する依存 |
| --- | --- | --- |
| `internal/model` | 永続データ、状態定数、要求・結果の型 | CLI、TUI、ファイルI/O |
| `internal/engine` | 入力検証、タスク操作、DAG検査、日付、表示値計算 | Cobra、Bubble Tea |
| `internal/storage` | ロック、読込、保存、スキーマ検証の入口 | CLI/TUI表示 |
| `cmd` | Cobraの引数処理、engine呼出、出力、終了コード | 独自の業務ルール |
| `internal/tui` | Bubble Teaによる入力状態と描画、engine呼出 | 独自の保存処理 |
| `main.go` | コマンド起動とプロセス終了 | 業務ロジック |

engine内のServiceがRepositoryインターフェースを使用し、storageが実装する。グラフ・進捗計算は副作用のない関数に分離する。時刻はClockとして注入し、日付のテストを再現可能にする。

概念上のインターフェース（採用ライブラリのAPIではない）:

```go
type Repository interface {
    Read(ctx context.Context) (Document, error)
    Update(ctx context.Context, expectedRevision *uint64,
        mutate func(*Document) error) (Document, error)
}
```

Updateは排他ロック取得、最新データ読込、revision照合、複製データへの変更、全体検証、保存、ロック解放を一つの処理として扱う。mutate失敗時は元データもファイルも変更しない。ロック中に対話入力や描画を待たない。

## 4. データモデル

### 4.1 保存ドキュメント（Q01/Q02/Q12の提案）

```json
{
  "schema_version": 1,
  "revision": 1,
  "next_id": 2,
  "tasks": [
    {
      "id": 1,
      "title": "全体設計",
      "status": "todo",
      "progress": 0,
      "progress_mode": "auto",
      "created_at": "2026-10-21T00:00:00Z"
    }
  ]
}
```

未作成時の論理状態はschema_version=1、revision=0、next_id=1、tasks=[]。読取だけではファイルを作成しない。IDは正の整数、next_idは既存最大IDより大きい。IDとrevisionの上限到達時はエラーにし、桁あふれで再利用しない。ID型は提案としてint64へ統一し、基本設計のintとの差分を実装時に明記する。

Taskは基本設計の各フィールドを保持し、progress_modeを追加する。日付は時刻なしのYYYY-MM-DD、作成・完了日時はUTCのRFC3339文字列。未設定の親、日付、完了日時は省略する。依存IDは重複除去し昇順で保存する。

保存時のprogressは手動指定値または葉の進捗であり、親の集計値とは区別する。集計値は保存せず、表示用TaskViewのeffective_progressに計算する。自動計算へ切替時は保存進捗を0へ戻す案とし、最後の子がなくなった自動モードの親は葉として0を表示する。

### 4.2 不変条件

- IDの重複、存在しない親・依存先、自己参照、循環を拒否する。
- statusはtodoまたはdone。progressは0〜100。doneなら保存progress=100、completed_atあり。todoならcompleted_atなし。
- progress_modeはautoまたはmanual。葉は保存progressを表示し、親のautoだけが集計対象。
- created_atは編集で変更しない。doneの再実行は成功扱いとし完了日時を変更しない。
- start_dateとdue_dateが両方あればstart_date <= due_dateとする提案。
- 不正な保存データを空データ扱いしない。未知のスキーマや未知フィールドを読み捨てて上書きしない。

既存の実装・旧データ形式は確認されていないため、自動移行は設計しない。将来の形式変更では別途移行手順とバックアップを設ける。

## 5. 入力と業務ロジック

### 5.1 入力規則（Q11の提案）

- titleは前後の空白を除去し、空文字、改行、タブ、ESC等の制御文字を拒否する。日本語・絵文字を保持する。表示時にも端末制御シーケンスを出力しない。
- IDは正の10進整数。0、負数、小数、範囲外を拒否する。
- 日付は厳密なYYYY-MM-DD、today、+Nd（Nは0以上の整数）。ローカル日付を操作受付時に一度取得し、暦日加算する。無効日とオーバーフローを拒否する。日付は着手の強制制限に使わない。
- editの未指定は維持、noneはparent/dep/start/dueの解除。titleの文字列noneは通常のタイトル。progress解除はQ02のautoを用いる。
- --depはカンマ区切りと繰返し指定を受け付け、editでは集合全体の置換。例: `--dep 2,3 --dep 4`。noneとIDの併用は拒否する。基本設計の`<id...>`はこの構文に具体化する提案。
- editで変更フラグがない場合は使用方法エラー。複数フラグの更新は全件成功または全件失敗とする。

### 5.2 操作

| 操作 | 更新内容 | 主な検証 |
| --- | --- | --- |
| Add | next_idを割当、todo、作成日時設定、next_id増加 | タイトル、日付、親、依存、進捗 |
| Edit | 指定された属性だけ置換 | 変更後のドキュメント全体 |
| Done | status=done、progress=100、完了日時設定 | 存在、Q04の方針 |
| Undone | status=todo、完了日時削除 | Q06の方針 |
| Remove | 対象または子孫集合を削除 | cascade指定、集合外からの依存参照 |

Addで-pを指定した場合はmanual、省略時はautoとする提案。-p 100だけではdoneにしない。doneのタスクへの100未満の進捗指定は拒否し、先にundoneを要求する。親や依存関係、タイトル、日付はdoneでも変更できる案とする。

自動進捗はdoneを100として優先し、todoのmanualは保存値、todoのautoで子ありは直下の子のeffective_progress平均の切り捨て、葉は保存値とする。子変更後は祖先を再計算する。親statusの自動変更は行わない。

blockedは依存先に一つでもtodoがあるとき成立する。「すべて未完了の場合だけ」ではない。blocked_byには未完了依存IDのみを列挙し、親や開始日からは推論しない。完了済みでも依存先がtodoなら関係上の警告は表示できるが、--blockedの既定対象はtodoのみ。

### 5.3 グラフ

ID→TaskとParentID→子ID列を構築する。参照存在を確認後、白・灰・黒の訪問状態によるDFSで閉路と経路を検出する。親子、依存それぞれと、Q08採用時は結合グラフを検査する。エラー例には`#1 -> #3 -> #1`の経路を付ける。

深い階層でも処理可能なよう、実装は明示スタックを用いる。検査・進捗計算はO(V+E)、順序確定のソートはO(V log V)を目安とする。削除集合は親子だけを辿り、依存先を巻き込んで削除しない。

## 6. ストレージと並行実行

保存先は基本設計どおり`~/.tque/tasks.json`。ホーム解決失敗はエラーとする。テストは一時ディレクトリを注入し、実ユーザーデータを使わない。

### 6.1 排他処理案

`~/.tque/lock`を対象にOSのファイルロックを使用する方式を提案する。ファイルの存在そのものをロックとせず、異常終了後に手動削除を要求しない方式を選ぶ。ロックファイルは解放時に削除しない。Windows/Unixの実装または採用ライブラリは未選定。ネットワーク共有上の利用保証は対象外とする案。

読込も同じロック下で行い、書込途中の状態を参照しない。データディレクトリが存在しない読込は空状態を返す。更新時にディレクトリを作成する。ロック待機はcontextで中断可能にし、提案値5秒でタイムアウトを返す。全プロセスが同じロック規約に従うことを前提とし、外部エディタによる直接書換えは保護できない。

### 6.2 更新手順

1. ロックを取得し、最新JSONを読んで形式・不変条件を検証する。
2. expectedRevision指定時は一致確認。不一致なら変更せず競合エラー。
3. ドキュメントを複製し、変更と全体検証を行う。
4. 実変更があればrevisionを1増加。無変更なら保存しない。
5. 同じディレクトリの`tasks.json.tmp`へ完全なJSONを書き、Sync、Closeを行う。
6. OS別の置換処理でtasks.jsonを置換する。
7. 必要な永続化処理を行い、結果を返してロックを解放する。

固定tmp名はロック所有者だけが操作する。前回残留したtmpは自動復元に使わず、次回保存時に扱う。エラー時も本体を削除してからリネームする方式は使用しない。

基本設計はos.Renameによるアトミック置換を要求しているが、全対象OSでの上書き・アトミック性・電源断耐性は未検証。Windowsを含むOSごとのAPI契約を確認し、必要なら専用実装に置き換える。原子的な可視性と電源断後の永続性は別の受入項目とする。

置換前の失敗は保存未完了と返す。置換後の永続化確認失敗は「保存結果の確認が必要」と区別し、Addを自動再試行しない。ロック解放失敗も成功に隠さず記録する。壊れたJSONは元ファイルを保持して停止し、初期化・切捨てをしない。

### 6.3 TUIとCLIの同時利用

TUIは一覧のrevisionと編集開始時のrevisionを保持する。保存は最新データに対し要求を適用するが、revisionが異なる場合は拒否する。再読込後も入力案を保持して利用者に再操作を求める。無関係なタスクの変更でも競合になる保守的な設計とする。

追加提案としてrキーで再読込する。初期版では常時監視を行わず、起動時・操作成功時・競合時・明示再読込時に表示を更新する。

## 7. CLI詳細

基本設計のadd/edit/done/undone/rm/lsを実装対象とする。引数なしまたは--tuiでTUIを起動し、サブコマンドと--tuiの併用は拒否する提案。TUI起動時に対話端末がなければ明確なエラーを返す。

| 項目 | 提案仕様 |
| --- | --- |
| 正常出力 | stdoutへ結果。失敗説明はstderr |
| 終了コード | 0成功、1業務・保存・競合エラー、2引数エラー |
| ls | Q09の対象をID昇順で表示 |
| --tree | 親子順で表示。フィルタ対象の祖先を文脈行として残し、対象外であることを表示 |
| --blocked | todoかつblocked。--all併用時はdoneの関係上の警告も対象 |
| --json | 表示用の行をJSON配列で出力。色と通常メッセージを混ぜない |
| --tree --json | 拒否する提案。階層はparent_idから復元可能 |
| 空一覧 | 通常表示は対象なし、JSONは[]、終了コード0 |
| --help/--version | 保存領域へアクセスせず出力 |

JSON行はTaskの各属性とeffective_progress、blocked、blocked_byを持ち、保存ドキュメントとは別の公開形式とする。--jsonでは文脈用祖先を混入しない。フラグの正当性は保存処理を呼ぶ前に確認する。

## 8. TUI詳細

一覧、テキスト入力、削除確認、保存中、エラー表示を状態として扱う。選択は行番号ではなくタスクIDで保持し、削除時は近傍行へ移す。ウィンドウサイズ変更時は表示幅とスクロール範囲を再計算する。

| 操作 | 状態遷移と処理 |
| --- | --- |
| j/k・上下 | 一覧の選択移動。末尾と先頭で停止 |
| Space | 対象のdone/undone要求 |
| +/- | 表示進捗±10を0〜100へ制限してmanual指定。doneの減算は先にundoneを促す |
| a/A | タイトル入力。Aは選択タスクを親として保持 |
| e | 現在タイトルを初期値に編集 |
| s/d | 日付入力。空欄で解除 |
| l | カンマ区切り依存ID入力。空欄で解除 |
| x/Delete | 対象と削除件数を表示。子ありなら子孫削除を明示して確認 |
| Enter/Esc | 入力確定・取消。取消時は保存しない |
| q/Ctrl+C | 一覧では終了。入力中のqは文字、Ctrl+Cは未確定入力を破棄して終了 |
| r（追加提案） | 一覧を再読込 |
| p（追加提案） | 進捗入力。0〜100またはautoを指定 |

削除確認は既定を取消とし、明示的な肯定入力だけで実行する。子孫集合外からの依存があればQ05に従って拒否し、参照元IDを表示する。

確定操作ごとに保存し、成功後に表示を更新する。終了時の全件上書きはしない。保存中は二重更新を受け付けず、終了要求は保存結果が判明してから処理する。入出力はBubble Teaの非同期コマンドから行い、結果メッセージで状態を更新する。

日本語・結合文字・絵文字はバイト数で切らず、端末表示幅を考慮する。幅不足ではタイトルを省略し、極小画面ではサイズ不足表示を行う。blockedは色だけでなく文字でも示す。入力中のj/k等は編集文字として扱う。エラー後も入力を保持して修正できるようにする。

## 9. エラー設計

engine/storageからは型付きエラーを返し、UIが表示する。例: InvalidInput、NotFound、CycleDetected、ReferencedTask、RevisionConflict、LockTimeout、CorruptData、UnsupportedSchema、StorageFailure、CommitUncertain。

エラーには操作、対象ID、原因となる参照ID等を含める。成功と確認できない保存を成功表示しない。保存エラー時の次操作は再読込を基本とする。無限リトライや破損データの自動修復は行わない。

## 11. ビルド・配布・ライセンス

利用者の指示に基づき、実装時には最低限次を用意する。

- `scripts/build-release.ps1`: リリースバイナリ作成。失敗時は非0終了。
- `scripts/build-installer.ps1`: Inno Setupによるインストーラー作成。-Sign指定時に環境変数CODESIGN_CERTを利用してアプリ実行ファイル、インストーラー、アンインストーラーへ署名する。
- `installer/tque.iss`: インストール対象、アンインストール、署名処理の構成。
- `docs/version-update-checklist.md`: バージョン変更時に更新する実ファイル一覧。

CODESIGN_CERTの値の形式、署名ツール、タイムスタンプ先、既存スクリプトとの互換性は未確認。値をログへ出さず、署名失敗時に未署名の成功成果物として扱わない。アンインストーラー署名の具体的方法はInno Setupの公式仕様を確認して実装する。

インストール範囲、PATH変更、対応CPU、初回バージョンは配布設計時に利用者と決める。アンインストールでタスクデータを自動削除しない案とする。今回はスクリプトやパッケージを作成しない。

Cobra、Bubble Tea、Lip Glossと推移依存のバージョン・Go要件・ライセンスを採用前に確認し、必要な著作権表示を同梱する。基本設計にGo 1.22+とあることだけから、現行ライブラリとの互換性や最低バージョン維持方針を断定しない。
