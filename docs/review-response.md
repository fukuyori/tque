# 詳細設計レビューへの評価と対応

更新日: 2026-10-21

対象は[第1版](detailed-design-reviewed-v1.md)に対する[Claude Codeレビュー](claude-review.md)。第2版へ反映した結果と後続の仕様変更を記録する。[現行詳細設計書](detailed-design.md)は第7版。本記録はロクの評価であり、レビュー原文を改変するものではない。

| 指摘 | 評価 | 第2版への対応 |
| --- | --- | --- |
| R01 手動進捗 | 一部採用。自動集計が「ほぼ動かない」は過大 | 4.3節で葉から親になっても固定継続と明記。manual表示と解除操作を定義 |
| R02 進捗状態の矛盾 | 採用。レビューの修正案にもdone=100との衝突があるため組み直した | 4.3節に状態・遷移表。auto切替と子の増減で保存値を保持、done/undoneはmode維持 |
| R03 読込ロック | 採用。共有ロックの追加は不要 | 4.1/6.1節でデータとlockを区別。読込/更新とも排他、未作成時の順序を明記 |
| R04 Windows保存 | 採用。ただし再試行必須とはしない | 6.2節でtmpの処理、未変更の失敗と結果不明を区別。OS別検証表を追加 |
| R05 差分 | 一部採用。毎操作保存やTUI確認は基本設計と必ずしも矛盾しない | 2.1節に変更・追加・具体化を区別した差分表 |
| R06 関係モデル | 採用。辺の反転だけでは意味の問題を解決しない | Q08/5.3節で包含と先行条件を分け、別々に循環検査する案。可否例を追加 |
| R07 復旧 | 一部採用。不正データで停止する方針は維持 | 9章に手動復旧手順。破損データ用一覧・修復機能は追加しない |
| R08 blocked | 採用。追加フィールドは不要 | 5.2/7章でstatusと独立した判定、表示・JSON・フィルタを統一 |
| R09 CLI | 採用 | 7.1節に入力可否、出力書式、UTF-8、JSON属性、undone無変更成功を明記 |
| R10 TUI | 採用。親変更UIは追加しない | 8.1節でrevision、初期値、連打、終了、選択、競合、空一覧を具体化 |
| R11 試験 | 選別して採用 | 10章に組合せ・日付境界・Windows・出力・TUI状態試験。既存と重複する試験は統合 |
| R12 その他 | 個別採用 | 保存先変更は追加しない。ロック中断を技術検証へ、通知先と終了コード3、型・日時差分を明記 |

評価上の優先項目はR02、R03、R06、R04。設計上の矛盾を整理することと、OSの保証を確認することを区別する。本文修正だけをもってWindows実機の問題が解消したとは扱わない。

利用者から未確定部分をClaude Codeと確定する指示を受け、第2版草案と基本設計の全文を再度渡した。仕様の採否、配布条件、タイトル長・性能目標、残存矛盾を決定するよう依頼し、回答を[共同検討記録](claude-decisions.md)に保存する。依頼は前回同様の非対話・safe-mode・MCP制限・Readのみの構成で実行する。

## 共同決定の完了と最終調整

Claude Codeは終了コード0で完了し、回答全文を確認した。渡した草案は[detailed-design-decision-draft.md](detailed-design-decision-draft.md)に保存。Q01〜Q16の決定を現行詳細設計に反映した。第1版のレビューは第1版を対象とし、現行版への評価と取り違えない。

Claude Codeの回答から次を調整して最終仕様とした。

- 他OS/CPUのクロスビルドとユニットテストを初版の必須作業にはしない。クロスビルド成功と対象OS上でのテスト実行は別であり、初版はWindows 11 x64を検証・配布対象とする。
- go.modの最低値は依存だけでなく自コードの言語機能も満たす値にする。実際のビルド検証版と区別する。
- バージョンの値の定義元はVERSIONだが、更新チェックリストにはリリースノートや利用文書の確認も含める。
- タイトル200コードポイントを採用。貼付けの切捨てはせず入力エラーを通知し、CLI/TUIで入力内容を黙って変えない。
- 「next_idが唯一の方式」という説明は採用しない。他方式の可能性は否定せず、単純で要件に合うため採用する。
- revisionのint64統一は表現統一として採用。第2版草案でuint64が仕様矛盾だったという理由は採用しない（元のJSON出力表のint64指定はタスクIDに対するもの）。
- 第5.2節に残っていた「-p指定ならmanual」を「数値指定ならmanual」に修正し、add -p autoとの不一致を解消。
- done中のTUI +/-はmodeも含め無変更とし、undoneを促す。pによる明示的なモード変更は第4.3節どおり許可する。
- 性能値は採用する設計目標として記載し、未計測であることと計測手順を明示する。

本体MIT、module tque、初回0.1.0、ユーザー単位インストールとPATH登録を確定した。権利者の正式表記、署名環境、OS API契約、依存バージョンは、根拠を取得して記入・検証する項目として残す。これらを検証済みとは扱わない。

現行版全体をClaude Codeへ再送した最終再レビューは行っていない。共同決定回答とロクの最終調整を反映し、文書内の参照・状態定義を確認した。アプリ実装・ビルド・配布は未実施。

## 第3版: 設定ファイルによる保存先指定

利用者の「設定ファイルを使用し、保存場所を指定できるようにしたい」という依頼に基づき、Q16の保存先固定方針を変更してQ17を追加した。上のR12対応およびClaude Code回答の「保存先変更は追加しない」は第2版時点の判断であり、現行仕様ではない。

~/.tque/config.jsonのdata_dirでデータディレクトリを指定し、本体・一時ファイル・ロックを同じ指定先へ配置する。設定省略時は~/.tqueを使用する。相対パスの基準、ホーム展開、設定エラー、再起動による反映、手動移行、アンインストール時の保持を第6.4〜6.5節へ追記した。設定例と検証計画も追加した。

第1版・共同検討草案・Claude Code回答は履歴として保持する。第3版をClaude Codeへ再レビュー依頼したものではない。今回もアプリコードや実ユーザーの設定ファイルは作成していない。

## 第4版: Windows・macOS・Linuxを必須対象に変更

利用者の「windows, macos, linuxで動作しなければならない」という指示に基づき、Windows限定だったQ10を改訂しQ18を追加した。第2版の最終調整とClaude Code回答のWindows限定方針は現行仕様ではない。

3 OSでCLI/TUI、共通JSON、設定ファイルによる保存先指定を提供する。各OSのamd64/arm64を設計対象とし、OS別のロック・置換・端末処理、ネイティブ実行環境での試験、配布物からの起動を受入条件に加えた。WindowsのInno Setupと署名仕様は維持し、macOS/Linux用のビルド・アーカイブ作成手順を追加した。

設定は3 OSとも~/.tque/config.jsonを使用し、ホーム相対の共通設定例を追加した。OS間のデータ移行、Unix系パス・権限・端末復帰も検証対象とした。OS最低版やライブラリ要件、macOS署名・公証は根拠を取得する技術検証項目として記録する。

今回も設計変更のみで、各OSの実装・ビルド・動作確認は未実施。第4版のClaude Code再レビューも未実施。

## 第5版: 優先度「高」の6項目を採用

利用者の採用指示に基づきQ19を追加。即時検索、期日・着手可能フィルタとソート、階層移動・折り畳み、状態別ヘルプ、PowerShell/Bash/Zsh/Fish補完、1世代の保存前バックアップを初版に含めた。

検索・フィルタのCLI/TUI共通判定、検索中の祖先表示、集計対象、折り畳みとの相互作用、既存キーとの衝突回避、バックアップ失敗時の本体保護と手動復旧を記載した。複数選択・Undo・TUIからの親変更は今回採用しない。コードの移植ではなく機能・操作方針の採用である。

参考: [RonDOの検索・ヘルプ・補完](https://github.com/roniel-rhack/rondo)、[PMの階層操作・フィルタ](https://github.com/pbower/project_management)、[ruskの保存前バックアップ](https://github.com/tagirov/rusk#storage)。画面の配色・列幅等に関する追加提案は確定仕様へ入れていない。実装・動作検証・第5版のClaude Code再レビューは未実施。

## 第6版: 推奨画面構成の採用と再検討項目の保留

第5版と画面案第1版をClaude Code・Antigravityへ渡して独立レビューを実施した。[比較・評価](screen-review-summary.md)と両者の回答原文を保存している。

利用者の「再検討に関しては、一旦保留し、推奨で進める」という指示に基づきQ20を追加し、ツリー一覧＋下部詳細、独立した通知欄、読み取り専用の全文詳細画面を第8.3節で採用した。CLIとTUIは値の意味・表記を共有し、画面上の配置は分ける。

保存結果不明後の再送方式、manual短縮、通知と全文詳細のキー、列幅・最小サイズ、Unicode追加制限、配色等は第8.4節で保留として管理する。レビューの具体案を一括採用せず、既存仕様を維持する。アプリ実装・描画・各OSでの検証は未実施。

## 第7版: 初期実装と利用者の追加回答

利用者の「実装に進めて」に基づき、CLI/TUI・保存処理・テスト・ビルドスクリプトを作成した。追加確認で外部資料・依存取得等を許可され、Enterで全文詳細・Escで戻る、検索入力中の左右は文字カーソル移動、80x24を基準に幅を調整する推奨案で進める回答を得た。具体化した操作は第8.5節へ記録した。

著作権者名と署名情報への回答は「検討」。正式名義を推測せずLICENSE.templateを用意し、署名スクリプトの対応形式と未検証事項を明示した。実行結果は[実装・検証記録](implementation-status.md)を参照。コードの外部レビュー、署名、公開は実施していない。
